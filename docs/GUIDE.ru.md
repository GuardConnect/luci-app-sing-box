# Подробное руководство

[README](../README.md)

## Начало работы

1. Откройте **Services → Sing-Box**. В «Настройки» включите службу, задайте язык, уровень журнала и при необходимости HWID. Автоматический User-Agent следует версии активного ядра.
2. В «Подписка» добавьте HTTPS URL. Название назначается по домену; источник можно переименовать, обновить, удалить, назначить по умолчанию и настроить автообновление. Доступен импорт VLESS-ссылок и base64.
3. В «Сеть» выберите uplink, например `wan (eth0)`, и создайте интерфейс и firewall-правила. Логическое имя OpenWrt (`sb0`, например) отличается от устройства TUN (`sb-tun0`).
4. В «Маршрутизация» задайте правила и их выходы. Теперь сервер выбирается **только здесь**: отдельно для каждого правила и для выхода по умолчанию. В выпадающих списках показаны название, адрес и порт; эмодзи отрисовываются локальными SVG.
5. Используйте «Проверить / предпросмотр», затем «Сохранить и применить». Внутренняя маршрутизация по умолчанию включена; выход по умолчанию — **«Прямое подключение»**. Поэтому трафик, не совпавший с правилом, идёт напрямую, пока вы не выберете другой выход.

«Перезапустить» использует сохранённые настройки; «Остановить» выключает управляемую службу. Общая кнопка «Сохранить и применить» сохраняет UCI и применяет изменения без дополнительного перехода в Unsaved changes.

## Маршрутизация

Правила выполняются сверху вниз. Поддерживаются точные домены, суффиксы, ключевые слова, **регулярные выражения Go/RE2**, **geosite**, GeoIP, IP/CIDR источника и назначения, порты и диапазоны, TCP/UDP/ICMP, распознанный протокол, IP-версия и частные адреса. Между полями выбирается AND/OR, поддерживаются инверсия и правило для всего трафика. Для одного поля значения объединяются по OR. Правила можно включать, дублировать и перемещать.

Выходы: прямое подключение, блокировка или конкретный узел из любой подписки. Отдельного выбранного глобального сервера и имени профиля больше нет. Старые ссылки на глобальный сервер в правилах переводятся в идентификатор конкретного узла; старый выход по умолчанию «Выбранный сервер» заменяется прямым.

Geosite и GeoIP преобразуются в современные удалённые `.srs` rule-set SagerNet, а не в удалённые из новых ядер поля `geosite`/`geoip`. Доступны GitHub и зеркало jsDelivr; собственные HTTPS rule-set поддерживают binary/source. Начальные загрузки проверяются ядром и кешируются на роутере. Дальше Sing-Box обновляет их с заданным интервалом (по умолчанию 24 часа). Для удалённых наборов используется API ядра 1.14+ (`http_client`, `initial_path`).

Есть шаблоны частных IP, geosite рекламы и UDP 443, импорт/экспорт JSON конструктора и просмотр сгенерированного route. Это собственный формат конструктора, а не импорт полного профиля Throne. «Сохранить маршрутизацию» сохраняет правила без перезапуска, «Сохранить и применить» проверяет и перезапускает службу с откатом при ошибке. При ручном JSON разрешено сохранять правила, но для их применения нужно вернуться к генерации из GUI.

Определение доменов и протоколов включается отдельно. TLS ECH и шифрование могут помешать распознаванию имени. Служебное правило DNS остаётся первым и не перекрывается пользовательскими правилами.

### Два режима перехвата трафика

- **PBR — существующие правила**: `auto_route=false`, `auto_redirect=false`. В PBR выберите созданный логический интерфейс. Конструктор обрабатывает трафик, направленный в TUN пакетом PBR.
- **Автоматические маршруты — без PBR**: ядро создаёт IPv4-маршруты TUN и nftables-перехват (`auto_route=true`, `auto_redirect=true`). Перед применением отключите PBR; одновременно включённые режимы не разрешены. Uplink привязывается явно, конфликтующие routing_mark удаляются. Частные и служебные диапазоны исключены для сохранения доступа к локальным сетям. PBR для этого режима не обязателен и больше не является зависимостью исходного пакета.

На рабочем роутере оставлен режим PBR. Автоматический режим проверен запуском настоящего ядра в отдельном сетевом namespace, без изменения маршрутов и nftables основной сети. Он настраивает IPv4; IPv6-перехват не заявлен.

## Пинг

Вкладка «Серверы» переименована в **«Пинг»**. Здесь выбирается подписка, метод, DNS и таймаут; выбора рабочего сервера больше нет.

- **TCP Connect** измеряет установку TCP-соединения именно с портом VLESS на физическом uplink. Это не проверка VLESS-авторизации.
- **Диагностика** независимо проверяет ICMP и TCP порта VLESS.
- **HTTP(S) URL через VLESS** запускает отдельный loopback-экземпляр, жёстко направленный через проверяемый узел, без пользовательских правил, автоматических маршрутов и прямого fallback. Успех требует HTTP 2xx/3xx и корректного TLS. Измеряется время до первого байта. В списке есть Google, Cloudflare, Apple и собственный URL.

DNS выбирается явно: стандартный dnsmasq → HTTPS DNS Proxy, Cloudflare, Google, Quad9, AdGuard, Яндекс, OpenDNS или свой IP. Для URL-проверки этот DNS разрешает и имя VLESS-сервера, и домен тестового URL. Выбор касается только проверки и не меняет основной DNS роутера.

**Замеры запускаются только кнопкой.** Открытие вкладки и смена списка, метода, DNS или URL их не запускают. Старые значения не подгружаются в таблицу; результаты очищаются перед запуском и при изменении параметров. Поздние ответы от старых параметров отбрасываются. Кнопка доступна повторно после успеха и ошибки. «Остановить проверку задержки серверов» отменяет текущее фоновое задание и его временные процессы, пропускает оставшиеся серверы и сохраняет уже показанные результаты. После подтверждённой отмены можно сразу запустить новую проверку. Массовая проверка выполняется одним фоновым заданием с промежуточными результатами: до 6 TCP/ICMP-узлов или 2 URL/VLESS-узлов одновременно. Интерфейс опрашивает прогресс раз в 250 мс. DNS-ответ для одинакового имени используется повторно только в пределах запуска TCP/ICMP; сами задержки каждого узла измеряются отдельно. ICMP использует три echo-запроса с шагом 100 мс и медиану, с проверкой идентификатора и случайной метки ответа. Таймаут TCP/URL сохраняется.

## Подписки, HWID и DNS

Поддерживается до 20 источников. Подписка по умолчанию определяет список, открываемый первым, и не меняет выходы маршрутизации. Автообновление: 0 — выключено, 5–10080 минут — интервал; cron проверяет сроки каждую минуту. Неудачная загрузка сохраняет прежний список. Нельзя удалить или обновлением потерять узел, используемый активными правилами.

HWID отправляет загрузчик подписки в `x-hwid`; дополнительно доступны `x-device-os`, `x-ver-os`, `x-device-model` и User-Agent. Кнопка перерегистрации создаёт HWID только для выбранного источника и сохраняет его после успешного импорта; провайдер может посчитать его новым устройством. Клиент не удаляет прежнюю регистрацию у провайдера.


Импортируются текстовые/base64 списки VLESS TCP, WebSocket, gRPC, HTTP/H2, TLS, Reality, Vision. JSON Sing-Box, Clash YAML, XHTTP и VLESS Encryption не импортируются. Сертификаты проверяются; неподдерживаемые узлы пропускаются с предупреждением.

## Остальные вкладки

«Версии» управляет официальными стабильными ядрами с SHA-256, проверкой конфига и откатом. «Конфигурация» открывает ручной JSON-редактор с `sing-box check`. «Журнал» показывает записи управляемого процесса, поддерживает копирование, обновление в реальном времени, паузу и автопрокрутку. При скрытой вкладке браузера polling журнала приостанавливается.

## Исходники и сборка


Основные файлы: `singbox-ui.js`, `singbox-routing.js`, `singbox-choices.js`, backend `root/usr/libexec/singbox-gui`, компилятор `singbox_routing.py`. Переводы: `tools/i18n.json`, `i18n-messages.json`, `i18n-routing.json`; генерация — `python3 tools/build-i18n.py`. Локальные 4009 SVG Twemoji v17.0.3 (~10 MB до сжатия), MIT/CC-BY 4.0, включены вместе с лицензиями; `tools/vendor-emoji.py` воспроизводит их загрузку. Во время просмотра внешние CDN не нужны.

Настройки: `/etc/config/singbox_gui`; подписки, правила, HWID и ручной JSON: `/etc/singbox-gui/`; временные задания: `/var/run/singbox-gui/`. Исходный архив не включает пользовательские URL, UUID и SSH-пароли. Подробности проверок — в `VALIDATION.md`.

Официальные источники: [TUN](https://sing-box.sagernet.org/configuration/inbound/tun/), [правила](https://sing-box.sagernet.org/configuration/route/rule/), [действия](https://sing-box.sagernet.org/configuration/route/rule_action/), [rule-set](https://sing-box.sagernet.org/configuration/rule-set/), [SagerNet geosite](https://github.com/SagerNet/sing-geosite). Организация конструктора основана на поведении [Throne](https://github.com/throneproj/Throne/blob/32ee312fadb615a5f12b2e18a386aa99c86ed03d/include/ui/setting/RouteItem.ui); код Throne не копировался.
