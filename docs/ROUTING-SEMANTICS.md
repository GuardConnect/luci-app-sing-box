# Правила маршрутизации: совместимость с Throne и Sing-Box 1.14.4

Конструктор сохраняет свой формат профиля, а перед запуском преобразует его в JSON Sing-Box. Внешний вид редактора не изменён.

## Как объединяются условия

Режим AND теперь создаёт обычное правило Sing-Box, как генератор Throne. Это **не** логическое AND между каждым заполненным полем:

- Точный домен, суффикс, ключевое слово, регулярное выражение и IP назначения — альтернативы внутри группы назначения.
- Точный порт и диапазон портов — альтернативы внутри группы портов.
- IP источника и частный IP источника — альтернативы внутри группы источника.
- Разные группы, версия IP, сеть и протокол ограничивают правило совместно.
- Geosite и GeoIP преобразуются в современные SRS rule-set. Несколько категорий и пользовательские наборы сохраняются вместе, без перезаписи. Семантику содержимого наборов определяет ядро: простой плоский набор может объединяться с соответствующими группами основного правила; сложные и инвертированные наборы имеют собственные условия.

Например, `domain: ["a.test"]`, `domain_suffix: ["b.test"]`, `port: [443]` означает HTTPS-порт для `a.test` **или** `b.test` и его поддоменов. Раньше приложение ошибочно требовало совпадения обоих доменных полей.

Явный режим OR остаётся расширением редактора: достаточно совпадения любого заполненного поля. Инверсия применяется к пользовательскому условию, а ограничение входом `tun-in` находится снаружи инверсии. Порядок правил сохраняется; отключённые правила пропускаются. DNS и sniff остаются перед пользовательскими правилами.

## Проверки

`tests/routing_semantics_live.py` сравнивает сгенерированный JSON с независимо заданными обычными правилами на настоящем ядре **1.14.4**: 100 HTTP-запросов через локальный SOCKS, положительные и отрицательные случаи, инверсия, regex, IP, порты, протоколы и rule-set. Наборы в этом тесте локальные и детерминированные; он не проверяет доступность внешних каталогов.

`tests/test_routing_semantics.py` проверяет структуру JSON, порядок, отключённые правила, match-all, OR, объединение категорий и строгие типы числовых полей. Сохранение конфигурации дополнительно использует `sing-box check`, включая проверку RE2 ядром.

Тесты не заменяют длительную эксплуатацию конкретного роутера. Они не устанавливают причину ранее наблюдавшейся потери DHCP. Автоматический режим и DHCP проверяются отдельно; настройки Windows Throne нельзя целиком переносить на OpenWrt.

## Совместимость существующих профилей

После обновления и повторного применения профиль AND с несколькими полями одной группы получает штатную семантику Sing-Box. Это намеренное исправление поведения; перед применением можно посмотреть JSON в редакторе. Одиночные доменные условия не меняются.

Источники: [официальные правила Sing-Box](https://sing-box.sagernet.org/configuration/route/rule/), [rule-set](https://sing-box.sagernet.org/configuration/rule-set/), [Throne](https://github.com/throneproj/Throne). Текущая документация содержит также поля 1.15: они не добавлены в генератор для 1.14.4.
