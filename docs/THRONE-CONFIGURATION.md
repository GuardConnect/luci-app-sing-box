# Конфигурация по структуре Throne

Пример: [throne-style-openwrt.json](../examples/throne-style-openwrt.json). Это корректный шаблон Sing-Box 1.14.4, но адрес VPN и UUID демонстрационные. Перед использованием нужны настоящие параметры сервера и правильное имя WAN-устройства. Пример не устанавливается автоматически и не заменяет пользовательские правила.

## Структура

- log: журнал ядра.
- dns: локальный dnsmasq, далее существующий HTTPS DNS Proxy.
- inbounds: TUN с gVisor для автоматического режима.
- outbounds: прямой выход, loopback для DNS и конкретные VLESS-серверы.
- route: DNS, распознавание домена, пользовательские правила; final=direct для нового профиля.

Текущий профиль Throne использует прямой выход по умолчанию и отдельный VLESS для YouTube. Пример воспроизводит этот порядок. Существующие выбранные выходы GUI не сбрасываются.

## Отличия от Windows Throne

На маршрутизаторе LAN/DHCP должны оставаться доступными. Поэтому strict_route=false и исключены частные, loopback, link-local, multicast, reserved/broadcast и 0.0.0.0/8. Дополнительные специальные исключения — защитная мера, а не доказанная причина прежнего отказа DHCP.

В Throne сохранены MTU 1500, адрес 172.19.0.1/24 и Google DoH. Пакет сохраняет настроенные пользователем MTU и TUN-адрес (по умолчанию 1400 и 172.30.255.1/30), а основной DNS остаётся dnsmasq → HTTPS DNS Proxy. Локальный mixed-прокси 2080 на роутере автоматически не открывается. IPv6-перехват не включается.

В Sing-Box 1.14 auto_route по умолчанию включает dns_mode=hijack. Для основного DNS пакета явно выставлено dns_mode=disabled, чтобы не добавлять второй DNS-перехват поверх HTTPS DNS Proxy. Служебное правило hijack-dns обрабатывает запросы, которые всё же поступили в TUN. Для отдельного DNS внутри Sing-Box сохраняется hijack.

PBR-режим остаётся на system stack; автоматический режим теперь использует gvisor. Это соответствует ядру 1.14.4. В 1.15 параметр stack объявлен устаревшим: дальнейшее обновление генератора требует отдельной проверки.

## Что установлено при проверке DHCP

На роутере после удаления Sing-Box dnsmasq работает; в сохранившемся журнале есть DHCPACK для ПК. Записи не позволяют восстановить точную причину прежнего сбоя.

В изолированных Linux network namespace запущены отдельные dnsmasq и udhcpc с виртуальной LAN. Адрес успешно получен без Sing-Box, со старым system-TUN и с новым gvisor-TUN. Поэтому утверждать, что старый stack или отсутствие broadcast-исключения вызвали потерю адреса, нельзя. Этот тест не воспроизводит весь firewall4, физический bridge и Windows-клиент.

45 backend-тестов прошли на временном ядре 1.14.4. Рабочие LAN, PBR и службы роутера не переключались. Пакет не переустанавливался.
